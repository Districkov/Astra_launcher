# ASTRA Launcher: Переход FiveM → RAGE:MP (3-шаговая система)

## Контекст

Полный переход с FiveM на RAGE:MP. Текущий лаунчер построен на Tauri v2 + Svelte 5 + Rust.
- **Лаунчер**: ASTRA Launcher управляет RAGE:MP — проверяет файлы, качает кэш, патчит и запускает
- **RAGE:MP**: Имеет свой лаунчер `RageMP.exe`, который запускает `GTA5.exe`
- **Кэш**: `client_resources/` в папке Rage (стандартная структура RAGE:MP)
- **Патчи**: Скачиваются с сервера, применяются через WriteProcessMemory к процессу
- **GTA V**: Версия зафиксирована (не обновляется автоматически)
- **Поддержка FiveM**: Удаляется полностью

## Полный флоу запуска (нажатие "Играть")

```
Пользователь нажимает "Играть"
  │
  ├─ Шаг 1: Проверка файлов клиента
  │   ├─ Скачиваем манифест (SHA-256 хэши всех файлов)
  │   ├─ Сравниваем с локальными файлами
  │   └─ Если есть расхождения → скачиваем только изменённые
  │
  ├─ Шаг 2: Проверка серверного кэша
  │   ├─ Запрашиваем cache_info.json (версия кэша)
  │   ├─ Сравниваем с локальной версией
  │   └─ Если нужна обнова → скачиваем delta или полный архив
  │
  ├─ Шаг 3: Скачивание патчей
  │   ├─ Запрашиваем patches.json с сервера
  │   └─ Получаем массив {name, offset, original, replacement}
  │
  └─ Шаг 4: Запуск с патчингом
      ├─ CreateProcessW("RageMP.exe", CREATE_SUSPENDED)
      ├─ Для каждого патча: ReadProcessMemory → валидация → WriteProcessMemory
      ├─ ResumeThread
      └─ RageMP.exe запускает GTA5.exe → подключение к серверу
```

## Шаг 1: Скачивание чистых файлов клиента

### Что делает
Хранит «замороженную» сборку RAGE:MP + GTA V на своём сервере. При запуске проверяет SHA-256 хэши файлов. Скачивает только если файлов нет или хэши не совпадают.

### Новые Tauri команды

| Команда | Описание |
|---------|----------|
| `check_client_files` | Скачивает манифест, сравнивает хэши. Возвращает `{valid, missing: [{path, sha256, size}], outdated: [...], total_size}` |
| `download_client_files` | Скачивает недостающие/изменённые файлы. Эмит `client-download-progress` с `{downloaded, total, percent, current_file}` |

### Структура манифеста (хостится на сервере)

```json
{
  "version": "1.0.0",
  "gta_version": "1.0.2699.0",
  "files": [
    {"path": "GTA5.exe", "sha256": "abc123...", "size": 723456789},
    {"path": "dinput8.dll", "sha256": "def456...", "size": 123456},
    {"path": "RageMP.exe", "sha256": "789abc...", "size": 2345678},
    {"path": "plugins/ragemp.dll", "sha256": "...", "size": ...}
  ]
}
```

### Rust реализация

**`manifest.rs`** — проверка файлов:
```rust

    pub sha256: String,
```

- Хэширование через `sha2` crate (SHA-256)
- Рекурсивный обход файлов в `rage_dir`
- Пропуск папки `client_resources/` (это кэш — отдельная проверка)

**`downloader.rs`** — скачивание с прогрессом:
```rust

    client_dir: &Path,
    files: &[FileEntry],
    base_url: &str,

```

- Скачивание через `reqwest` с стримингом
- Эмит `client-download-progress` для каждого файла
- Проверка SHA-256 после скачивания
- При ошибке хэша — повторное скачивание (1 retry)

## Шаг 3: Патчинг в памяти (Runtime)

### Что делает
Скачивает патчи с сервера. Запускает RageMP.exe в приостановленном состоянии, внедряет байты через WriteProcessMemory, возобновляет процесс.

### Новые Tauri команды

| Команда | Описание |
|---------|----------|
| `download_patches` | Скачивает `patches.json` с сервера. Возвращает массив патчей |
| `launch_patched` | `CreateProcessW(CREATE_SUSPENDED)` → `WriteProcessMemory` для каждого патча → `ResumeThread` |

### Структура patches.json (на сервере)
```json
{
  "version": "1.0.0",
  "gta_build": "2699",
  "ragemp_version": "1.1",
  "patches": [
    {
      "name": "Connection bypass",
      "target": "RageMP.exe",
      "offset": "0x1A3F20",
      "original": "89 45 E8 83 7D E8 00",
      "replacement": "90 90 90 90 90 90 90"
    },
    {
      "name": "Manifest check",
      "target": "RageMP.exe",
      "offset": "0x2B1C40",
      "original": "75 2C 48 8B",
      "replacement": "90 90 48 8B"
    }
  ]
}
```

### Rust реализация (`patcher.rs`)

```rust
pub struct Patch {
    pub name: String,
    pub target: String,        // "RageMP.exe" или "GTA5.exe"
    pub offset: u64,           // RVA offset
    pub original: Vec<u8>,     // Ожидаемые байты (для валидации)
    pub replacement: Vec<u8>,  // Патч-байты
}

pub struct PatchManifest {
    pub version: String,
    pub gta_build: String,
    pub ragemp_version: String,
    pub patches: Vec<Patch>,
}

pub async fn download_patches(patches_url: &str) -> Result<PatchManifest, String>

pub fn launch_patched(
    exe_path: &Path,
    server_address: &str,
    patches: &[Patch],
) -> Result<u32, String>  // → PID
```

### Алгоритм `launch_patched`

```rust
use windows::Win32::System::Threading::*;
use windows::Win32::System::Memory::*;
use windows::Win32::Foundation::*;

fn launch_patched(exe_path: &Path, server_address: &str, patches: &[Patch]) -> Result<u32, String> {
    // 1. Создаём процесс в приостановленном состоянии
    let mut si: STARTUPINFOW = unsafe { std::mem::zeroed() };
    si.cb = std::mem::size_of::<STARTUPINFOW>() as u32;
    let mut pi: PROCESS_INFORMATION = unsafe { std::mem::zeroed() };
    let cmd = format!("{} +connect {}", exe_path.display(), server_address);

    unsafe {
        CreateProcessW(
            None,
            &windows::core::HSTRING::from(&cmd),
            None, None, FALSE,
            CREATE_SUSPENDED,  // <-- Ключевой флаг
            None, None,
            &si, &mut pi,
        ).map_err(|e| format!("CreateProcess failed: {}", e))?;
    }

    // 2. Патчим каждый байт
    for patch in patches {
        let base_addr = pi.hProcess.as_ptr() as usize + patch.offset as usize;

        // 2a. Читаем текущие байты
        let mut current_bytes = vec![0u8; patch.original.len()];
        unsafe {
            ReadProcessMemory(
                pi.hProcess,
                patch.offset as *const _,
                current_bytes.as_mut_ptr() as *mut _,
                patch.original.len(),
                None,
            ).map_err(|e| format!("ReadProcessMemory failed: {}", e))?;
        }

        // 2b. Валидация: байты совпадают с ожидаемыми?
        if current_bytes != patch.original {
            // Байты не совпадают — патч не применим (версия изменилась)
            unsafe { TerminateProcess(pi.hProcess, 1); }
            return Err(format!("Patch '{}' validation failed: bytes mismatch", patch.name));
        }

        // 2c. Записываем патч
        unsafe {
            WriteProcessMemory(
                pi.hProcess,
                patch.offset as *const _,
                patch.replacement.as_ptr() as *const _,
                patch.replacement.len(),
                None,
            ).map_err(|e| format!("WriteProcessMemory failed: {}", e))?;
        }
    }

    // 3. Возобновляем процесс
    unsafe { ResumeThread(pi.hThread); }

    Ok(pi.dwProcessId)
}
```

### Безопасность и валидация
- **Проверка original bytes**: Если байты не совпадают → патч НЕ применяется (процесс убивается). Это защищает от применения патча к неверной версии.
- **Версионирование patches.json**: Поле `gta_build` и `ragemp_version` для информации (проверка происходит по original bytes).
- **Одноразовость**: Патчи применяются только при запуске. Процесс создаётся с `CREATE_SUSPENDED` — если патчинг провалился, процесс убивается, ничего не происходит.

```typescript
async function handlePlay(playClickSound, serverOnline, setDiscordRpcPlaying) {
  playClickSound();
  if (isLaunching) return;
  isLaunching = true;

  try {
    // Фаза 1: Проверка + скачивание файлов клиента
    launchPhase = 1;
    const checkResult = await invoke("check_client_files");
    if (!checkResult.valid) {
      // Слушаем прогресс скачивания
      const unlisten = await listen("client-download-progress", (e) => {
        downloadPercent = e.payload.percent;
        statusMessage = `Скачивание: ${e.payload.current_file}`;
      });
      await invoke("download_client_files");
      unlisten();
    }

    // Фаза 2: Проверка + скачивание кэша
    launchPhase = 2;
    const cacheCheck = await invoke("check_server_cache");
    if (cacheCheck.needed) {
      const unlisten2 = await listen("cache-download-progress", (e) => {
        // обновляем прогресс
      });
      await invoke("download_server_cache");
      unlisten2();
    }

    // Фаза 3: Скачивание патчей
    launchPhase = 3;
    const patches = await invoke("download_patches");

    // Фаза 4: Запуск с патчингом
    launchPhase = 4;
    await invoke("launch_patched", { patches });

    // Успех
    setDiscordRpcPlaying();
    statusMessage = "GTA V запущен ✓";
  } catch (error) {
    // Обработка ошибок по фазам
  } finally {
    isLaunching = false;
    launchPhase = 0;
    launchProgress = 0;
  }
}
```

## Auto-поиск папки Rage

### Стратегия поиска `find_rage_dir()`
1. Пользовательский путь из `config.json` → `rage_dir`
2. `%LocalAppData%\RageMP\`
3. `%LocalAppData%\Rage\`
4. `%USERPROFILE%\Desktop\Rage\`
5. `C:\Rage\`, `D:\Rage\`
6. Рекурсивный поиск `GTA5.exe` в `%LocalAppData%\Rage*\` (глубина 3)
7. Поиск `.lnk` ярлыков на рабочем столе с "Rage" / "RAGE" / "RAGE:MP" в имени
8. Если найдена папка с `GTA5.exe` + `RageMP.exe` → это Rage
9. Валидация: проверяем что `client_resources/` существует (или создаем)
