### THE ROOT CAUSE (high confidence)
- **`play.astra-rp.fun` resolves via public DNS (8.8.8.8) to `185.176.94.21`**, but the
  actual server is at **`89.35.130.191`** (user-confirmed working). Stale A record.
- `astra-rp.fun` → Cloudflare (188.114.96/97.x); `cdn.astra-rp.fun` → Cloudflare.
- So the server advertises FQDN `play.astra-rp.fun`, the client resolves it for the
  secure channel → lands on the WRONG/dead IP `185.176.94.21` → "Can't establish
  secure connection". Manual raw-IP connect bypasses the FQDN, so it works.
- The hosts file currently only maps the FAKE domain
  `89.35.130.191  astra-89-35-130-191.gta5rp.com  # astra-launcher`
  (public DNS for that fake domain = NXDOMAIN; it's hosts-only).

### Fix direction
1. **Best (server/DNS):** update `play.astra-rp.fun` A-record → `89.35.130.191`
   (Cloudflare/registrar). Or set `conf.json "fqdn"` to match what clients use,
   or `""`; or set `"enable-http-security": false`.
2. **Client workaround (ASTRA can write via UAC «Применить»):** add
   `89.35.130.191  play.astra-rp.fun  # astra-launcher` to hosts so the client
   resolves the FQDN correctly without waiting for DNS.
3. `allow-cef-debugging: true` on the server = possible CDP automation path.
